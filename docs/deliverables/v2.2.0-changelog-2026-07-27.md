# v2.2.0 — App-aware mascota (2026-07-27)

La mascota ahora detecta qué app está en foreground y cambia su **mood** y **micro-reacciones** según el contexto. No es RAG, no es "entiende qué haces", es **reactividad contextual**.

## 🎯 Cambios principales

### Polling del foreground app (cada 8 segundos)

Nuevo servicio `src/services/app-detector.js` que consulta la ventana en foreground vía PowerShell (Windows API: `GetForegroundWindow` + `GetWindowThreadProcessId` + `GetWindowText`).

```js
startDetector(({ processName, windowTitle, category }) => {
  safeSend(petWindow, 'app-changed', { processName, windowTitle, category, mood, wagTargets });
});
```

- Polling cada 8 segundos
- Solo emite `app-changed` cuando la **category** cambia (no en cada poll — sin spam)
- Non-Windows: graceful no-op (devuelve `{ name: '' }`)
- ~1% CPU, ~50ms por poll

### Categorización: process name → category

Nuevo módulo `src/core/app-categories.js` con 7 categories y 70+ process names:

| Category | Ejemplos | Mood | Wag targets (speed, amp) |
|---|---|---|---|
| **code** | vscode, webstorm, sublime, pycharm, cursor | `calm` | 0.04, 0.8 |
| **creative** | photoshop, figma, sketch, blender, canva | `excited` (low amp = curious) | 0.06, 1.0 |
| **office** | excel, word, powerpoint, libreoffice (soffice) | `sleepy` | 0.02, 0.5 |
| **browser** | chrome, firefox, edge, brave, opera, vivaldi | `excited` | 0.10, 1.3 |
| **social** | slack, discord, telegram, whatsapp, teams, zoom | `happy` | 0.08, 1.2 |
| **game** | steam, league, valorant, minecraft, cs2 | `excited` | 0.12, 1.5 |
| **system** | explorer, settings, task manager | `calm` | 0.04, 0.8 |
| **unknown** | (default) | (no change) | (no change) |

Case-insensitive substring matching. Pattern conflict = la primera regla que matchea gana.

### Mood reactivo (usa el lerp de v2.1.0 M4)

Cuando llega `app-changed` al renderer, los **wag targets** se actualizan. El **lerp M4** interpola gradualmente a la nueva velocidad — la transición es suave, no hay jump cut en la cola.

```js
window.petAPI?.onAppChanged?.(({ processName, windowTitle, category, mood, wagTargets }) => {
  if (wagTargets) {
    tailWagSpeedTarget = wagTargets.speed;        // M4 lerp los interpola
    tailWagAmplitudeTarget = wagTargets.amplitude;
  }
  if (!SEEN_APPS.has(category)) {
    SEEN_APPS.add(category);
    showSpeech(APP_GREETINGS[category]);           // one-shot por category
  }
});
```

### Speech bubble: saludo one-shot por category

La primera vez que la mascota ve cada category, dice un saludo contextual. Luego se calla (no spam en cada poll).

| Category | Saludo |
|---|---|
| code | "¡Modo código! A romperla." |
| creative | "¡A crear cosas!" |
| office | "¿Trabajo de oficina? Zzz..." |
| browser | "¿Navegando?" |
| social | "¡Asocializar!" |
| game | "¡A jugar!" |
| system | (sin saludo — apps del sistema son ruido) |

## 🛠 Detalles técnicos

### Archivos nuevos

- `src/core/app-categories.js` (90 líneas) — categorización + mood/wag maps
- `src/services/app-detector.js` (110 líneas) — polling PowerShell
- `test/app-categories.test.js` (20 unit tests)
- `test/app-detector.test.js` (15 unit tests)

### Archivos modificados

- `main.js`:
  - require `startDetector` / `stopDetector` / `CATEGORY_MOODS` / `CATEGORY_WAG_TARGETS`
  - `app.whenReady()`: arranca el detector
  - `before-quit`: para el detector
- `preload.js`:
  - expone `onAppChanged` vía contextBridge
- `src/renderer.js`:
  - listener de `app-changed` con SEEN_APPS set para one-shot greeting

### Wire completo

```
[OS foreground] 
  ↓ (poll 8s, PowerShell + Win32 API)
[app-detector.js] → { processName, windowTitle, category }
  ↓
[main.js] → IPC 'app-changed' (solo si category cambia)
  ↓
[preload.js] → window.petAPI.onAppChanged
  ↓
[renderer.js] → tailWagSpeedTarget/AmplitudeTarget (lerp M4) + showSpeech
```

## 🔐 Privacy

- Todo es local — el process name NUNCA se envía a ningún servidor
- Solo se loguea internamente para debug (`logDebug('APP CHANGED', ...)`)
- El usuario puede desactivar el detector comentando la línea en `app.whenReady()` (M5) o haciendo un flag

## 🚀 Lo que NO está en este release

- macOS / Linux support (Windows only — el PowerShell hardcodea)
- Custom reactions por app específica (e.g., "Photoshop → 'le sacaste los ojos a alguien?'")
- Whitelist editable desde el dashboard
- Learning de patrones de uso (e.g., "los viernes a las 5pm cerrás todo")
- Idle detection integration (ya existe idle-monitor, no se cruza con este feature)
